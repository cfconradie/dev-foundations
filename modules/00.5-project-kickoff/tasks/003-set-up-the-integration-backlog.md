# Task 003 — Set up the integration backlog

**Concept:** not every worthwhile thing to learn maps cleanly onto one pricing calculator (a
generic sorting-algorithm drill doesn't become part of the app just because you wish it did) — the
honest move is to name that up front and track it, not pretend everything ties in or quietly let
it become a disconnected exercise anyway.

**Where this goes:** concept-lab — this task itself doesn't log a real backlog entry (nothing's
been built yet to have detours from), but the judgment it builds is what you'll use for real
starting in module 02.5.

**Step 1 — build it yourself, no AI:** read `INTEGRATION-BACKLOG.md` in full. Then write, in your
own words (a few sentences, doesn't need to live anywhere but this task's commit), what you think
distinguishes a task that *should* directly build the project from one that's legitimately a
detour. Try to name one topic from the course's stated scope (DS&A, security, system design —
whatever you already know is coming) that you predict will be a detour, and one you predict will
tie in directly, before you've seen those modules' actual task lists.

**Done when (step 1):** you've written your own prediction (detour vs. direct) for at least one
topic in each direction, committed on your task branch.

**Step 2 — AI review pass:** tell the AI your two predictions and ask: "For the topic I predicted
would be a detour, is there actually a way to tie it into a pricing/quote calculator that I'm
missing — or is my instinct right that it's better logged as a detour?" This is a real question,
not a rhetorical one — a stronger answer than your first guess is a legitimate outcome here. Note
what you learned in `PROGRESS.md`.

**Stretch (optional):** none — this is a short setup task.
