# Integration backlog

Most tasks in this course build a real piece of `PROJECT.md`'s app directly. A few can't — a
generic algorithm drill, a system-design case study about a URL shortener — because the topic
doesn't map cleanly onto a pricing calculator. Those still have to earn their place, so every one
of them gets logged here with a note on when/how it gets applied back into the project (or an
honest reason it never will).

A task that adds an entry here isn't done until the entry is either closed (the tie-back actually
happened, with a link to the task that did it) or explicitly marked "interview-prep breadth, not
applicable" — which is itself a real decision, not a shrug.

## How to use this file

When a task's own file tells you to log an entry here, add a row to the open table below. When a
later task closes one (applies the technique/pattern back into the real project, or the review
checkpoint task decides it's breadth-only), move the row to the closed table with the date and
the task that closed it.
